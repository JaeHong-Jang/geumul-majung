# HW 하윤 UX·기능 구현 프롬프트

아래 문서 전체를 개발 에이전트에게 전달할 수 있다. 이 프롬프트는 2026-11-05의 조사와 이번 P0 범위를 재현·유지보수하기 위한 것이다. 기능이 이미 구현되어 있으면 다시 만들지 말고 현재 코드를 확인해 부족한 부분만 수정한다. P1·P2 항목은 별도 요청 없이 구현하지 않는다.

## 역할과 작업 목표

당신은 운송기사의 업무 흐름과 접근성을 함께 책임지는 프런트엔드 개발자다. 이 저장소의 **HW 하윤** JavaScript 프로토타입을 개선하고 도메인·실제 브라우저 검증까지 완료하라. 계획만 제시하고 멈추지 말고, 이미 승인된 범위의 로컬 수정·검증을 수행하라.

제품의 원안은 공장이 산업 부산물을 판매하고, 허가 재활용업체가 원료를 구매하며, 허가 운반업체가 운송하는 **잔재미/마대 장터**다. HW 하윤은 이 중 구미 기반 5톤 윙바디 기사의 콜 비교·수락·수거·도착 업무를 담당한다. 배출자가 항상 처리비를 내는 수거 신청 서비스로 바꾸지 말라. 운송기사에게 구매자의 검사·공장 등록·플랫폼 중재 권한을 부여하지 말라.

목표는 기사가 정차한 상태에서 다음을 이해하도록 만드는 것이다.

- 무엇을 어느 공장에서 어떤 구매자에게 운송하는가.
- 운임과 공차·적재거리, 상차 조건을 비교했을 때 어떤 콜을 선택할 것인가.
- 수락 전에 차량·상차·허가 조건에 무엇을 확인해야 하는가.
- 현재 단계, 실제 앱 조작 시각, 확인한 마대 무게와 검사 대기 상태는 무엇인가.

## 먼저 읽을 로컬 근거

저장소의 AGENTS.md와 현재 `DESIGN.md`를 따른다. 아래 파일을 읽고 기존 구성·행동을 파악한 다음 수정하라.

- `hw-hayoon/README.md`: 실행·제품 범위·검증 명령
- `hw-hayoon/docs/SOURCE_REVIEW.md`: 네 브랜치와 원본 A/B/C 검토
- `hw-hayoon/docs/GLOBAL_REFERENCES.md`: 공식 출처, 해석, P0/P1/P2 구분
- `docs/ARCHITECTURE.md`: 최신 계약 우선순위 10절 > 9절 > 8절. 이전 QA 기록을 현행 계약으로 단정하지 않는다.
- `hw-hayoon/src/domain.js`, `src/data.js`, `src/views.js`, `app.js`, `styles.css`: 상태·예시 데이터·화면·이벤트·반응형 스타일
- `hw-hayoon/tests/`, `scripts/browser-check.mjs`, `package.json`: 기존 검증과 증거 생성 방식

실제 거래·공공시스템과 연결되지 않은 로컬 예시 앱이다. 기존 서버·Flutter 디렉터리를 이번 요청 때문에 수정하지 말라. 다른 에이전트나 사용자의 변경을 되돌리지 말고 충돌하면 담당 범위를 조정하라.

## 유지할 기존 동작

메뉴는 **콜 찾기 / 내 운송 / 정산 관리 / 저장한 콜 / 내 정보**의 다섯 개를 유지한다. `#calls`, `#trips`, `#earnings`, `#saved`, `#profile` 라우트를 깨뜨리지 않는다.

검색·필터·정렬·저장·지도 선택과 상세 연결, 오프라인 수락 차단, 5톤 초과 차단, 운임 상한 검사, 활성 운송 중 중복 배차 차단을 유지한다. 수락한 콜은 모집 목록에서 제외한다. 마대 확인은 해당 콜의 마대 수를 기준으로 한다. 무게 차이 안내와 수거 전 배차 해제, 도착 후 구매자 검사 대기를 유지한다.

새로고침 복원, 예시 데이터 초기화, 정산 상태 구분과 기존 CSV 내보내기도 회귀 확인한다. 기존 저장 데이터에 새 필드가 없더라도 앱을 깨뜨리거나 과거 사건의 시각·측정값을 지어내지 않는다.

## P0 기능 1: 자원 운송 정보

상세와 운송 과정에서 **자원 운송 정보**라는 이름의 일관된 카드를 제공하라. 공인 인증서나 법정 여권처럼 보이게 만들지 않는다.

- 품목/재질, 예시 데이터 출처, 등록 등급, 등록 중량, 마대 수, 배출자와 구매자를 표시한다.
- 실제 기사 입력이 있는 경우 등록 중량과 **기사 확인 중량**을 분리한다. 수거 전에는 확인 전임을 표시한다.
- 실제 입력이 없는 오염도·순도·처리 방식은 `정보 없음` 또는 `확인 필요`로 표시한다. 임의의 98%·안전·재활용 적합 판정을 추가하지 않는다.
- 등급은 원본 예시의 등록 값이다. AI가 현장에서 재판정하거나 법정 허가를 대신한 것으로 표현하지 않는다.
- 긴 회사명·재질명과 모바일에서도 읽을 수 있게 줄바꿈한다.

## P0 기능 2: 최대 3개 콜 비교와 주행비 가정

콜 카드·상세에서 비교 선택을 추가·제거하고 선택 개수를 확인할 수 있게 하라. 네 번째 선택은 이해 가능한 안내와 함께 막는다. 선택 해제·전체 초기화를 제공한다. 저장 기능과 비교 선택은 서로 다른 상태다.

선택한 최대 3개 콜 ID와 주행비 설정을 브라우저에 보존한다. 손상된 저장값·중복·없는 콜 ID는 정리한다. 검색·필터를 바꿔도 선택 상태를 임의로 잃지 않는다. 수락 등 상태 변경 후 비교 대상이 유효한지 일관되게 처리한다.

비교 정보는 경로, 표시 운임, 공차거리, 적재거리, 합계거리, 공차 포함 km당 운임, 예상 주행비, **주행비 차감 참고액**을 포함한다. 콜의 운임 상한과 수락 뒤 확정 운임의 의미를 구분한다.

계산 계약:

- 합계거리 = 공차거리 + 적재거리
- 공차 포함 km당 운임 = 원 단위 반올림(표시 운임 / 합계거리)
- 예상 주행비 = 원 단위 반올림(합계거리 × 설정 원/km)
- 주행비 차감 참고액 = 표시 운임 − 반올림한 예상 주행비

기본값은 **450원/km, 시연용 가정**이다. 사용자 입력 범위는 **0~10,000원/km의 정수**이며 0도 유효하다. 거리 표시는 소수 첫째 자리까지 하되 계산에는 원본 거리 정밀도를 사용한다. km당 운임과 예상 주행비를 원 단위로 반올림하고, 반올림한 주행비를 빼서 참고액을 계산한다. 음수·소수 입력·범위 초과·NaN·Infinity·잘못된 저장값을 검사한다. 합계거리가 0이면 나눗셈 결과를 계산 불가로 처리해 NaN/Infinity가 화면에 나오지 않게 한다. 음수의 주행비 차감 참고액도 숨기지 않는다.

이 값은 통행료·노무·상하차 대기·보험·정비·감가·세금 등 전체 비용을 반영한 **순이익이나 실수령액이 아니다.** 화면에 `순이익`을 사용하지 않는다. 450원/km를 업계 권장단가로 설명하지 않는다. 모바일 비교표는 컨테이너 안에서 읽거나 스크롤하게 하고 페이지 전체가 옆으로 넘치지 않게 한다.

## P0 기능 3: 수락 전 조건 요약

기존 수락 대화상자 안에서 다음 정보를 읽기 쉬운 요약으로 제공하라.

- 내 차량 적재 한도와 콜 중량, 적합·초과 상태
- 지게차 있음/수작업 상차 등의 상차 조건
- 예시 허가 정보·코드 확인 수준과 추가 확인 필요 여부

이 요약을 이유로 체크박스 세 개를 새로 통과하게 만들지 않는다. 기존 운임 입력·수락 버튼과 검증을 유지한다. 예시 허가 정보를 정부 조회 완료나 실제 적법성 보장으로 표시하지 않는다. 확인할 근거가 없으면 그 상태를 드러내며 자동 확인한 것처럼 꾸미지 않는다.

## P0 기능 4: 운송 타임라인과 JSON 기록

활성 운송과 최근 운송 이력에서 수락·상차지 도착·무게 확인/운송 시작·하차지 도착·도착 확인 전송 등 실제 상태 전이를 읽을 수 있게 하라.

- 사용자가 실제로 수행한 시각을 ISO 형식으로 저장하고 화면에는 한국어로 이해하기 쉽게 표시한다.
- 기록되지 않은 과거 단계의 시각을 현재 시각이나 임의 값으로 채우지 않는다. `기록 없음`처럼 사실대로 표시한다.
- 단계별 기록이 새로고침 뒤에도 복원되고 같은 동작의 중복 기록이나 불가능한 순서가 생기지 않게 한다.
- 운송 ID, 품목·당사자·중량·확정 운임·단계/시각·상태를 참고용 JSON으로 내려받게 한다. 활성·최근 운송의 기록을 구분할 수 있어야 한다.
- 파일은 브라우저에서 생성하며 외부로 전송하지 않는다. 법정 인계서·정산서·공인 증빙을 대체하지 않는 **운송 참고 기록**임을 화면과 파일 정보에서 밝힌다.
- 도착 기록은 GPS 인증이 아니고 구매자 검사 완료도 아니다. 기사 도착 후 상태는 구매자 검사 대기로 유지한다.

## 이번에 구현하지 않을 기능

P1 후속 검토: POD·계량표 첨부, 실제 서버와 다자간 이력 공유, 귀로 연속 배차, 공적 허가 조회, 구조화된 오염·처리 정보 입력, 완전한 차량 원가 모델.

P2 검증: 기사 사용성 관찰, 비교 3개 제한의 적정성, 주행비 가정 이해도, 구매자 등급 스펙, 소량 묶음의 실거래·운영 비용.

이번 작업에서 GPS 추적, AI 사진 판별·자동 등급, 실제 결제·보험·정산·올바로 제출, POD 업로드를 추가하지 않는다. 자동 수익 보장, 근거 없는 탄소 수치, 순도·오염도 추정을 넣지 않는다. 전체 공장 좌표 자료나 외부 서비스의 이미지·화면을 복사하지 않는다.

## 기술·구현 제약

HTML/CSS/JavaScript ES modules, Node.js 22+의 기존 서버·테스트를 사용한다. TypeScript 전환, React 도입, 새 런타임·개발 의존성, 외부 CDN을 추가하지 않는다. 기존 Leaflet·지도·글꼴과 라이선스를 보존한다. 핵심 기능은 외부 네트워크 없이 작동해야 한다.

계산·상태 전이·저장값 정리는 DOM과 분리된 도메인 함수로 검증한다. 현재 파일 경계와 코딩 패턴을 우선하며, 이번 기능과 관계없는 대규모 리팩터링은 하지 않는다. 화면의 사용자 입력은 안전하게 렌더링하고 저장값·파일 내보내기에 필요한 데이터만 포함한다.

## 접근성·반응형 기준

- 실제 button/input/dialog와 연결된 레이블, 선택 상태의 텍스트·ARIA, 명확한 포커스를 사용한다.
- 대화상자 첫 포커스·키보드 이동·Escape 닫기·닫힌 뒤 원래 버튼으로 복귀를 확인한다.
- 비교 선택·최대 개수·오류·저장 결과는 색에만 의존하지 않고 필요한 경우 live 상태로 알린다.
- 주요 터치 영역은 44px 이상, 한글 입력 중 검색 흐름을 깨뜨리지 않고 긴 텍스트를 수용한다.
- 최소 375px·390px 모바일, 768px 태블릿, 1440px 데스크톱을 확인한다. 고정 비교 영역이나 하단 메뉴가 주요 버튼을 가리지 않게 한다.
- `prefers-reduced-motion`을 존중한다. 이동 중 조작을 유도하는 인터랙션은 넣지 않는다.

## 필수 도메인 검증

기존 테스트를 유지하고 변경된 행동의 경계에 테스트를 추가하라.

1. 비교 0/1/3개, 네 번째 차단, 선택 해제·전체 초기화, 중복·없는 ID·손상된 저장 데이터 처리
2. 주행비 0·450·10,000과 잘못된 값, 거리 합계·단위 운임·비용·음수 결과·0거리 처리, 설정 복원
3. 기존 오프라인·차량 초과·운임 상한·중복 배차 차단 유지, 수락 정보와 실제 규칙의 일치
4. 실제 단계 시각 기록·순서·중복 방지·새로고침 복원, 오래된 기록에 시각이 없을 때의 처리
5. JSON에 필요한 실제 기록과 참고용 의미가 포함되고 도착을 정산 완료로 바꾸지 않는지 확인
6. 기존 검색·필터·저장·마대 수/무게·검사 대기·초기화 회귀 확인

## 필수 브라우저 검증

기존 로컬 서버를 실행하고 격리된 브라우저 검사 흐름을 확장하라.

- 서로 다른 3개 콜을 비교하고 네 번째 차단을 확인한다. 비용을 바꾸고 새로고침해 비교 선택·가정의 복원을 확인한다.
- 상세의 자원 운송 정보에 등록/확인 중량과 누락 정보가 정확히 구분되는지 확인한다.
- 수락 전 적재·상차·허가 요약과 기존 검증이 보이며 불필요한 체크박스가 늘지 않았는지 확인한다.
- 수락 → 상차지 도착 → 모든 마대 무게 → 운송 → 하차지 도착 → 검사 대기 → 이력·JSON 흐름을 수행한다.
- JSON 다운로드 이벤트와 파일 내용을 확인한다. 외부 전송이 없는지 확인한다.
- 375/390px에서 다섯 메뉴, 비교·상세·수락·운송 화면의 가림·넘침과 키보드 포커스를 확인한다.
- 콘솔 오류, 요청 실패, 렌더링 예외와 기존 지도·다운로드 회귀를 확인한다.

저장소 루트에서 `cd hw-hayoon` 후 `npm run check`를 실행한다. 별도 터미널에서 `npm run dev`로 로컬 서버를 띄운 뒤 `npm run test:browser`를 실행한다. 다른 포트라면 기존 스크립트의 `BROWSER_TEST_URL`을 설정한다. 기존 명령이 현재 환경에서 실패하면 원인과 사용한 대체 확인을 기록하고 성공한 것으로 쓰지 않는다.

`check`는 현재 JavaScript 구문 검사·Node 테스트·정적 빌드다. 실제 실행하지 않은 ESLint·타입 검사·공식 접근성 인증을 통과했다고 표현하지 않는다. 이전 README의 통과 개수를 재사용하지 말고 이번 실행 결과를 읽어 보고한다.

## 완료 산출물과 보고

구현 파일, 필요한 도메인·브라우저 테스트, 최신 실행·기능 문서, 조사 근거와 이 프롬프트의 상태를 정렬하라. 검증 결과와 주요 화면 증거를 기존 `hw-hayoon/docs/` 방식으로 보관한다.

최종 보고에는 다음을 짧게 포함한다.

1. 실제 반영한 네 기능과 사용 경로
2. 주요 변경 파일과 그렇게 결정한 이유
3. 실행한 검증 명령·실제 통과/실패 결과와 스크린샷·결과 파일
4. 여전히 로컬 예시인 범위와 P1/P2로 남긴 기능
5. 재사용할 문서·프롬프트 위치

테스트가 실패하거나 주요 흐름이 막히면 복구 가능한 문제를 수정하고 다시 검증한다. 남은 오류·미검증을 숨기지 않는다. 실제 외부 배포·가입·결제·메시지 전송은 이 작업의 종료 조건에 포함하지 않는다.
