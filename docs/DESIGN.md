# 잔재미 앱 화면 기준

현재 UI 구현 기준은 `frontend/`의 React 웹 앱이다. 공통 헤더·카드·탭은 `frontend/src/shared/ui/shell/`, 역할별 화면은 `frontend/src/apps/`를 확인한다. 이전 Flutter 앱은 `archive/legacy/janjaemi-app/`, 독립 운송기사 시안은 `archive/legacy/hw-hayoon/`에 보존한다. 이들은 과거 참고 자료이며 현재 실행 대상이나 앞으로의 디자인 제약이 아니다.

아래의 Flutter 치수·원본 화면 관련 내용은 과거 이식 기록이다. 현재 코드 및 사용자가 요청한 UI 변경을 우선한다.

세 앱 색상은 `src/shared/theme.css`의 AppColors 한 벌이다. 브랜드 #286347, 바탕 #FAF8F3, 금색 #F2B544와 원본 등급·상태 색을 함께 사용한다. 판매자의 `styles/tokens.css`는 이 변수에 연결한다. 소셜 공급자 버튼은 카카오 노랑·구글 흰색이다.

로그인은 `shared/screens/Login.tsx` 하나를 쓴다. Flutter 기준 여백 24 / 상단 68 / 하단 40, 제목 24·줄높이 32.4, 역할 카드 간격 10·모서리 16·테두리 2·안쪽 16×14, 역할 아이콘 44, 입력 높이 50을 적용한다. 앱 역할은 초기 선택만 정하며 카드 선택은 버튼 문구만 바꾼다. 로그인 응답의 회사 역할로 세션 저장과 앱 이동을 결정한다. 세 앱 모두 `janjaemi:{buyer|carrier|seller}` 세션 키를 사용한다.

공통 화면은 `shared/screens/`, 부품은 `shared/ui/`, API는 `shared/api/`에 둔다. 구매자 화면은 `apps/buyer/{home,explore,listing,bundle,cart,purchase}`, 기사 화면은 `apps/carrier/{home,calls,trip,earnings,my}`로 분리한다. 판매자의 공통 화면 파일은 탐색 문맥을 연결하는 어댑터이며, 고유 등록·공동판매·재활용업체 화면 구조는 유지한다.

가입은 계정 → 사업장 → 승인 상태 두 단계와 결과 화면이다. 구매자·기사는 허가번호와 서버 폐기물 코드 선택이 필수이고, 기사는 차량 정보도 보낸다. 주소 검색 스크립트는 요청 시 로드한다. 주소 변환 결과가 없으면 서버 지역 중심을 선택하고 Leaflet 핀으로 보정한다. 검색 스크립트가 실패해도 직접 입력을 유지한다. 재설정·OAuth 토큰은 최초 앱 진입에서 주소에서 제거하고 메모리에만 유지한다. 요청 형식 `#token=`과 구현 반환 형식 `#/oauth?access_token=`을 함께 처리한다.

화면 문구는 명사형 또는 짧은 평서문을 사용한다. 계산으로 만든 묶음은 공동판매 묶음·운송 묶음 제안으로 표시하며, 서버 에이전트 결과인 판매 조언만 AI 조언으로 표시한다. 서버 응답 문구는 유지한다. 검증 오류의 detail 목록은 한국어 입력 안내로 바꾼다.

기사 운행 탭은 진행 주문의 검수·운송 화면으로 연결한다. 하단 탭은 목록·트럭·지폐 아이콘을 쓰며 세 앱의 마지막 탭은 마이다. 날짜는 한국 시간 기준 `11.04 (수)` 형식으로 표시한다. 지도는 실제 좌표의 직선 연결이며 길안내는 카카오맵으로 연결한다. 주유 쿠폰·탄소 감축량 등 근거 없는 값은 만들지 않는다. 구매자 성과 카드의 CSV는 내 정산 완료 거래의 실제 금액을 내려받는다.

시세 그래프는 실제 이력의 선만 그리며 알루미늄은 금색, 철·PP는 브랜드 초록이다. 보조 글자는 공통 `--font-secondary`(최소 14px)와 진한 회색 `--color-body`를 쓴다. 숫자·단위·설명이 넘치면 글자를 줄이지 않고 줄바꿈한다. 장바구니 구매 버튼은 본문과 분리된 하단 고정 영역에 두고 빈 상태에서도 비활성으로 유지한다. 로딩 화면은 393×852 캔버스, 로고 (114,155), 제목 y=323, 부제 y=381, 그림 (32,490)·329×170, 안내 y=726의 Flutter 수치를 공유한다.

검증은 `cd frontend && npm run check`, `npm run build`로 실행한다. 기존 거래·금액·검사·인계서 회귀 검사와 공통 로그인·역할 이동·가입·재설정·OAuth·문의·표시 문구 검사를 유지한다. 실제 브라우저 캡처는 실행 환경의 포트 바인딩 및 Chromium 실행 거부로 수행하지 못했다.


심사 보완 기준: 세 앱 마이는 `shared/screens/My.tsx` 하나로 표시한다. 머리 제목은 좌측 20px Bold이며 기사만 공통 머리 색 변수를 브랜드 초록으로 바꾼다. 프로필은 흰색·모서리 12px·안쪽 16px 카드와 역할 배지, 메뉴는 좌측 아이콘·우측 끝 화살표·최소 52px 행을 쓴다. 차량 정보 수정은 요약 카드에만 둔다. 판매자의 알림 설정과 고객센터도 공통 화면으로 연결한다.

하단 탐색은 `shared/ui/Navigation.tsx`의 `BottomTabs` 하나로 렌더링한다. 판매자 탭은 홈·등록자원·공동판매·거래내역·마이다. 공통 `SectionTitle`은 제목 줄바꿈을 허용하고 전체 보기 버튼 폭을 확보한다. 판매자 홈 추천은 `seller/home.recommended_recyclers`의 `id`, `name`, `region`, `distance_km`, `pickup_method`, `terms`를 표시하며 상세 `id`로 이동한다. 빈 목록은 재활용업체 보기 버튼만 표시한다. 요약 세 칸은 서버 목록을 집계해 수거·공동판매·인계 화면에 연결한다.

공통 터치 변수는 최소 44×44, 주요 버튼과 마이 메뉴는 52px다. 판매자 축소 캔버스에서도 실제 최소 크기와 보조 글자 14px를 보존한다. 매물 담기는 별도 44px 이상 텍스트 버튼이며 빈 장바구니는 매물 보러 가기로 탐색에 연결한다. 로그인은 입력 전에도 브랜드 버튼을 유지하고, 제출 시 첫 미입력 칸에 초점과 안내를 표시하며 서버 요청을 보내지 않는다.

운행 상태 카드는 전체가 스위치이며 저장된 상태만 운행 중·운행 대기 중으로 표시한다. 요청 조회를 제한하지 않는다. 빈 요청 문구는 현재 받을 수 있는 요청 없음으로 통일한다. 검색·등급·지역·최대 중량·저장함 조건이 실제 적용된 경우에만 필터 초기화를 표시한다. 필터 패널 열기와 정렬 변경은 목록을 제외하는 조건이 아니다.

로딩 트럭은 공장 우측 끝 뒤 x=82에서 출발한다. 바퀴는 연속된 원형 테두리와 원형 축이며 도착 체크는 2.5px 금색 링과 3.5px 선을 쓴다. 스플래시는 바탕 위에서 투명해진 뒤 제거해 상단 띠를 남기지 않는다. 이 환경에서는 Vite 포트 바인딩(EPERM)과 Chromium 실행(소켓 권한)이 거부되어 수정 후 브라우저 캡처는 수행하지 못했다.
