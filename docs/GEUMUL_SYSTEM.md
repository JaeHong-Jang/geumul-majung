# 그물마중 시스템 구조 (웹·앱·서버·AI)

2026-11-27 기준. 이 문서는 "지금 돌아가는 것"과 "현장 운영까지 가려면 무엇을 더 해야 하나"를 나눠 적는다.
API 칸 이름은 `docs/GEUMUL_API.md`, 데이터 설계 배경은 `docs/GEUMUL_BACKEND.md`.

## 2. 왜 이렇게 나눴나

| 결정 | 이유 |
|---|---|
| 화면 셋, 서버 하나 | 운영 담당은 큰 화면(대시보드), 집하장은 휴대폰(모바일 웹·iOS). 셋이 같은 반출 건을 보고 고쳐야 하므로 기록은 서버 한 곳에만 있다 |
| 계산은 서버가 최종 | 계산 규칙이 웹(`model.js`)과 iOS(`Model.swift`)에 두 번 있었다. 돈이 걸린 숫자(고객 절감, 운영료)가 기기마다 다르면 안 되므로 서버 값이 기준이고, 화면 계산은 입력 중 미리보기용이다. 서버 테스트가 팀원 시제품 테스트와 같은 숫자를 낸다 |
| 역할 셋 | 실증 흐름이 집하장(등록) → 운영(조건 확정) → 처리업체(계량·정산)로 나뉜다. 서버가 동작마다 역할을 확인하고 이력에 남긴다 |
| 버전 검사 | 두 사람이 같은 건을 고치면 나중 저장이 앞 저장을 덮지 않고 "새로 불러온 뒤 다시"를 돌려준다 |
| 서버가 꺼져도 시연 | 섬과 발표장은 인터넷이 불안하다. 서버에 닿지 않으면 화면이 기기 저장소로 돈다 |
| AI는 하네스 안에서만 | AI가 낸 문장은 근거(법 조문 id, 입력값, 계산식)가 있어야 화면에 나간다. 근거에 없는 숫자는 게이트가 막는다. 실행 순서는 설정 파일이 정하고 LLM이 바꾸지 못한다 |
| 숫자는 사람 말·서류에서만 | 말로 등록할 때 무게·마대 수·날짜는 규칙으로만 읽는다. 계량증명서 사진에서 읽은 숫자도 옮겨 적은 글에 그대로 있어야 남고, 사람이 확인하기 전에는 정산에 안 들어간다 |

## 3. 한 반출 건이 지나가는 길

| 단계 | 누가, 어느 화면 | 서버에서 일어나는 일 | AI |
|---|---|---|---|
| 1. 등록 | 집하장, 휴대폰 | `POST /shipments`: 반출번호 발급, 기본 조건 2개(그대로/로프 분리) 생성, 이력 "등록" | 말로 등록: 음성 → 글 → `gm_intake`가 칸 초안. 못 읽은 칸은 "직접 입력 필요" |
| 2. 점검 | 집하장·운영 | `GET /shipments/{id}/checklist` | `gm_check`: 생활/사업장폐기물 구분, 운반 신고·허가, 인계서 대상, 관리대장, 보증금, 로프 분리 효과, 재질 확인, 반입 신청 기한. 법 항목마다 조문 원문 보기 |
| 3. 조건 비교·확정 | 운영, 대시보드 | `PUT /quotes`, `POST /confirm`: 유효기간이 출항일 이후인 조건만 확정 | (확장) 품목별 구매자 제안 |
| 4. 출항·하역 | (배·차량, 앱 밖) | 출항일이 지나야 정산 가능 | |
| 5. 계량·검수 | 처리업체 | `POST /scans` → 초안, `POST /scans/{id}/confirm` → 확인 | `gm_scan`: 계량증명서 사진 → 칸 + 검산(글에 없는 숫자 비움, 총중량−공차=실중량, 법정 필수 5항목, 손글씨 경고) |
| 6. 정산 | 처리업체 | `POST /settle`: 인수량 ≤ 계량 총중량, 증빙번호 필수, 부분 인수면 사유 필수. 고객 절감·운영료·공헌이익 계산 | |
| 7. 기록 | 모두 | 이력(누가 언제 무엇을), 대시보드 숫자(`/summary`) | |
| 수시 | 모두 | | 법 질문: 폐어구 조문 57개에서만 답 |

## 4. AI 에이전트 목록

기존 잔재미 에이전트 14개 위에 그물마중 팀 3개를 더했다(`harness/harness.yaml`의 `gm` 팀).

| 에이전트 | 입력 | 출력 | LLM 쓰임 | 상태 |
|---|---|---|---|---|
| 말로 반출 등록 `gm_intake` | 음성 인식 글 | 어구 종류, 재질, 톤, 마대 수, 출항 일시, 점검 항목 | 안 씀(규칙). 현장 말이 짧고 칸이 정해져 있어 규칙이 더 정확 | 구현·테스트 |
| 반출 법 점검 `gm_check` | 반출 기록 | 조문 근거가 붙은 점검 목록 | 법 항목 쉬운 말 요약(게이트 통과 시만) | 구현·테스트 |
| 계량증명서 읽기 `gm_scan` | 문서 사진 | 칸 초안, 검산 결과, 정산 칸 제안 | 사진 읽기(옮겨 적기·칸 채우기) | 연결 완료: 로컬 Ollama `qwen2.5vl:7b`. 가상 증명서 2장에서 9개 칸 모두 읽음(오타 1건), 20~57초. 실제 계량소 서식·손글씨는 미시험 |
| 대화 도우미 `assistant`(기존) | 질문 | 관련 조문 최대 3개와 쉬운 문구 | 요약 문장 | 재사용 |
| 판매 가능 판정 `gm_grade` | 떼어 놓은 묶음(어구, 재질, 나온 곳, 섞임, 절단, 부착물) | 판매 후보·조건부·처리 대상, 팔려면 할 일, 받는다고 공개한 업체와 거리 | 안 씀(공개 조사 규칙) | 구현·테스트, 모바일 연결 |
| 서류 안내와 초안 `gm_docs` | 반출 단계, 판매 묶음, 확인한 계량증명서 | 필요한 서류 목록, 채운 칸과 직접 입력할 칸, 인쇄용 초안 | 안 씀 | 구현·테스트, 모바일 연결 |

**모델 고르기**: 글 LLM은 `LLM_PROVIDER`(ollama | claude | off), 사진 LLM은 `VISION_PROVIDER`(claude | ollama | off)와 `VISION_MODEL`. `deploy/run_gm.sh`의 기본값은 로컬 Ollama `qwen2.5vl:7b`(먼저 `ollama pull qwen2.5vl:7b`, 약 6GB, GPU 8GB에서 동작). 사진은 PC 밖으로 나가지 않는다.

## 5. 웹과 앱의 역할 나누기

| | 웹 대시보드 | 모바일 웹 | iOS 앱 |
|---|---|---|---|
| 주 사용자 | 운영 담당(우리 팀), 발주 기관 보고 | 집하장 담당, 처리업체 | 집하장 담당 |
| 주 작업 | 전체 현황, 조건 비교·확정, 정산 내역, 시연 초기화 | 등록, 점검 보기, 검수·정산 입력 | 등록, 사진·음성 입력 |
| 서버 연결 | 됨(`gm-api.js`) | 됨(`gm-api.js`) | 예정(`docs/GEUMUL_API.md` 6절) |
| 서버 없을 때 | 브라우저 저장소 | 브라우저 저장소 | 기기 저장소(UserDefaults) |
| 설치 | 없음 | 없음(주소만) | Xcode 빌드(Mac) |

같은 기능을 세 번 만들지 않기 위한 원칙: **화면은 보여 주기와 입력만, 판단과 계산은 서버.** 새 기능은 서버 API를 먼저 만들고 화면 셋이 부른다.

## 6. 데이터

| 표 | 내용 | 비고 |
|---|---|---|
| `gm_shipments` | 반출 한 건(화면 기록 모양 그대로 JSON), 상태, 버전 | 출항일은 JSON 안 문자열. 날짜로 찾는 기능이 생기면 칸을 뺀다 |
| `gm_scans` | 문서 사진 원본, 읽은 초안, 확인 여부, 확인자 | 원본은 지우지 않는다 |
| `agent_runs` | AI 실행 기록(어떤 에이전트가 어떤 주장을 냈고 무엇이 막혔나) | 말한 글 원문은 넣지 않는다, 옮겨 적은 글은 연락처를 가린다 |
| `companies` | 계정과 역할 | 잔재미 표 재사용 |

## 7. 지금 된 것과 현장 운영까지 남은 것

**된 것(테스트로 확인)**: 자원 순환 판매(판정 → 판매 등록 → 업체 매입 제안 → 운영 수락 → 집하장 몫 계산, 구매자용 판매 목록 `/market`), 업체 회신(지정 처리업체가 인수 조건을 직접 보냄), 서류 안내와 인쇄용 초안, 서버 계산·검증, 역할별 권한, 이력, 버전 검사, 웹 두 화면 서버 연결, AI 에이전트 3개 API, 모바일 웹의 AI 버튼(등록 화면 '글로 채우기·녹음', 반출 상세 '법·현장 점검·법 질문', 검수 화면 '계량증명서 사진'), 서버 끔 시연.

**남은 것(우선순위 순)**

1. 대시보드(운영 화면)에도 법 점검 표시. 모바일 웹에는 붙였다.
2. 사진 읽기 모델 연결(Claude API 키 또는 Ollama 사진 모델)과 실제 계량증명서 사진으로 시험.
3. iOS 서버 연결(Mac 담당).
4. 사람마다 로그인. 지금은 한 기기가 세 역할로 자동 로그인하는 시연 모드다.
5. 업체는 자기 건만 보기, 발주 기관 보고용 읽기 전용 계정.
6. 배포: 지금은 각자 PC에서 `deploy/run_gm.sh`. 현장 실증에는 고정 주소 서버와 PostgreSQL(잔재미 배포 설정 재사용)이 필요하다.
7. 날짜에 시간대 붙이기(`+09:00`), 출항일을 DB 칸으로 빼기.
8. 판매 확장: 판매 묶음과 처리 흐름의 무게 연동(판 만큼 처리 물량에서 빼기), 실제 매입가 견적으로 가정값 바꾸기, 판매 대금 정산 주체(시 소유 물량의 판매자) 확인.
