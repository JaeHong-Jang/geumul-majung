# 공장 위치 좌표를 얻는 방법 (조사일 2026-11-05)

앱은 거리 계산, 묶음 반경, 기사 지도에 쓰려고 좌표를 **DB에 저장**해야 한다. 그래서 "저장해도 되는가"가 가장 중요한 기준이다.

## 결론
1. **주소 입력:** 다음(카카오) 우편번호 서비스. 무료, 키 없음, 좌표는 주지 않는다.
2. **주소 → 좌표:** 행정안전부 **도로명주소 위치정보 요약DB**를 우리 DB에 올려 조회한다. 외부 API에 의존하지 않는다.
3. **승인 전 임시:** 행정안전부 **좌표제공 팝업API**로 변환한다.
4. **보정:** 어긋나면 사용자가 지도에서 핀을 옮긴다. 좌표에 출처(`coord_source`)를 남긴다.

지오코더 API(브이월드, 카카오, 구글)는 저장 제한이 있어 주 경로로 쓰지 않는다.

## 구현 순서
1. 우편번호 위젯으로 도로명주소를 받는다.
2. 좌표제공 API로 변환해 좌표와 `coord_source`를 저장한다. 키가 없으면 시·군 중심 좌표로 두고 `coord_source=region`으로 표시한다.
3. 요약DB 승인 후 시도별 파일을 표에 올려 주소로 조회한다. API는 보조로 남긴다.
4. 지도에서 핀 보정(`coord_source=user`).
5. 거리, 묶음 반경, 지도는 모두 우리 DB 값으로 계산한다.

## 사람이 신청할 것
- **좌표제공 API 승인키:** data.go.kr 또는 juso.go.kr. 신청 즉시 이용으로 안내됨. 일일 한도와 약관은 신청 화면에서 확인.
- **위치정보 요약DB:** business.juso.go.kr에서 신청서, 본인인증, 이용목적 심사. 처리 기간은 미확인(지자체 안내 한 곳에 10일이라는 말이 있었으나 확정 아님).

## 기존 데이터와의 관계
이전에 카카오로 만든 좌표(`data/21_공장좌표`)는 내부 분석용이고 앱 DB에 넣지 않는다. 공개 저장소에 올라갔던 `carrier-app/data/factories.js`도 같은 이유로 앱에 넣지 않는다.

## 미확인
요약DB 심사 기준·기간·좌표계, 팝업API 일일 한도와 약관 원문, 공공누리 제1유형 조건 원문, 카카오 로컬 전용 약관, 네이버 약관, 구글 현행 약관, 인허가 데이터 조건, 브이월드 이용약관(열람 실패), Nominatim 한국 품질.

## 좌표 키와 검색 키는 별개 (2026-11-05 확인)
- 좌표제공 API(`addrCoordApi.do`)와 주소검색 API(`addrLinkApi.do`)는 승인키가 따로다. 승인받은 좌표제공 키로 좌표 API는 정상 동작하지만(양재동 코드 → 37.469346, 127.040002) 같은 키로 검색 API를 부르면 `E0001 승인되지 않은 KEY`가 난다.
- 그래서 서버는 **다음 우편번호 위젯이 주는 행정 코드**(`bcode` → `admCd`, `sigunguCode`+`roadnameCode` → `rnMgtSn`, 건물 본번·부번, 지하 여부)로 검색 키 없이 좌표 API를 바로 부른다. 검색 키(`JUSO_SEARCH_KEY`)는 선택이며 있을 때만 코드가 없는 요청에 쓴다. 환경변수 이름: `JUSO_COORD_KEY`, `JUSO_SEARCH_KEY`. 키 값은 저장소에 넣지 않고 로그에도 남기지 않는다.
- 검색 응답의 `siNm`·`sggNm` 필드명은 테스트 키 응답으로 확인했다.
