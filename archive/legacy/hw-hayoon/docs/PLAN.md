# HW 하윤 구현·검증 계획

1. 네 브랜치의 제품 문서·운송 초안·구매자 앱·현재 서버 계약을 검토한다.
2. DESIGN.md에 기록한 A 지도+B 비교 목록+C 다음 행동 결합을 JavaScript로 구현한다.
3. 기존 예시 콜과 로컬 지도·글꼴을 재사용하고 운송 상태·검색·저장·정산 대기를 연결한다.
4. 운임 상한, 차량 적재량, 중복 배차, 마대별 확인, 단계 전환을 Node 내장 테스트로 검증한다.
5. 실제 브라우저에서 데스크톱·모바일과 핵심 여정을 검증하고 스크린샷을 보관한다.

종료 기준: 앱 실행, 모든 내비게이션/주요 버튼 동작, 테스트 통과, 화면 넘침·콘솔 오류 확인, 실행 방법·출처·서버 미연동 범위 문서화.

## 해외 레퍼런스 적용

1. 공식 공개 자료로 유사 원료 거래 서비스와 인접 소재·물류 서비스의 기능을 구분해 조사한다.
2. 운송기사 범위에서 자원 정보, 최대 3건 비교, 주행비 가정, 수락 전 조건, 운송 기록을 연결한다.
3. 순수 계산·선택 한도·입력 검증·저장 호환·운송 시각의 의미를 Node 테스트로 검증한다.
4. 브라우저에서 비교 선택/해제/한도/비용 변경/새로고침, 자원 정보와 미등록 항목, 수락·상차·도착 후 기록 내려받기를 검증한다. 기존 81개 검사의 주요 경계를 유지한다.
5. 1440/768/390/375px 화면, 대화상자 내부 넘침, 키보드 포커스와 오류 상태를 확인한다. 스크린샷과 시각 검토를 기록한다.
6. 공식 출처·사실/제안 구분·구현/후속 범위를 문서화하고 독립 실행 가능한 개발 프롬프트를 제공한다.

종료 기준: 외부 서비스 조회는 읽기만 수행, 추가 패키지 없음, 기존 사용자 작업 보존, 테스트·빌드·브라우저 검사 통과, 레퍼런스 분석과 프롬프트 파일 제공.
