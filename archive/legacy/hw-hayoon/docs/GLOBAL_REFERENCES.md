# 글로벌 사례 검토와 HW 하윤 UX 반영

조사 기준일: **2026-11-05**. 공식 공개 페이지와 도움말을 읽고, 현재 운송기사 프로토타입에서 검증할 수 있는 기능으로 범위를 좁혔다. 글로벌 시장 전체를 망라한 경쟁사 목록이나 업체별 성능 순위는 아니다. 폐자원 거래, 기업 자산 재사용, 자재 정보 관리, 화물 운송에서 관련 사례를 골랐다.

## 판단 요약

원안은 공장이 산업 부산물을 판매하고, 허가 재활용업체가 원료를 구매하며, 운반업체가 운송하는 B2B 장터다. **HW 하윤은 이 중 운송기사의 비교·수락·수거·도착 업무를 담당한다.** 사례를 따라 구매자·공장·건축 자재 관리 시스템까지 이번 앱에 추가하지 않는다. 원안의 근거와 현재 구현 범위는 [SOURCE_REVIEW.md](SOURCE_REVIEW.md), [DESIGN.md](../../DESIGN.md)를 참조한다.

이번 반영은 네 가지다.

1. 흩어진 품목·출처·중량·당사자 정보를 **자원 운송 정보** 카드로 묶는다.
2. 최대 3개 콜을 비교하고, 공차를 포함한 거리와 사용자 설정 주행비를 함께 계산한다.
3. 수락 화면에서 적재량·상차 방법·허가 정보를 한 번에 확인한다.
4. 실제 앱 조작 시각을 운송 타임라인으로 남기고 참고용 JSON으로 내려받는다.

이 선택은 아래 사례에서 관찰한 정보 구조를 우리 업무에 맞게 바꾼 **설계 추론**이다. 어느 서비스에도 동일한 네 기능이 그대로 존재한다고 주장하지 않는다. 기존 5개 메뉴, 검색·필터·지도·저장·마대별 무게·검사 대기 흐름을 유지한다.

## 조사 방법과 근거의 강도

| 근거 | 이번 조사에서 확인한 범위 | 확인하지 않은 범위 |
|---|---|---|
| 공개 목록·필터 | Cyrkl의 공급/수요/기업 구분, 필터 항목 | 로그인 뒤 매칭·성사율·실제 가격 |
| 공식 도움말 | Rheaply 작성·물류 절차, Madaster 여권 형식, Uber Freight 검색·운송 후 절차 | 계정·지역·요금제별 실제 제공 범위와 현장 결과 |
| 제품 소개·데모 페이지 | Recykal, EME, Cyrkl Copilot이 설명하는 기능 | 실제 계정에서의 작동, 정확도·절감률·수익·운영 성과 |
| 국내 서비스 소개 | 커버링의 방문수거·빌딩·오피스 서비스와 안내 구조 | 내부 기사 앱, 세부 배차 정책, 실거래 품질 |

페이지에 기능이 소개되어 있다는 사실과 기능의 효과가 검증되었다는 판단은 구분한다. 공개 화면의 통계·후기·절감률을 우리 제품의 성과 근거로 사용하지 않았다. 이미지를 복사하거나 화면 전체를 재현하지 않고 정보의 순서와 의사결정 구조를 참고했다.

## 관련 사례별 사실과 해석

### 1. Cyrkl — 체코 기반 유럽 폐자원 거래·운영 사례

**확인한 사실:** 공개 장터가 Offers, Demands, Companies로 나뉘고 Category, Location, Quantity, Form, Date of publication 필터를 제공한다. [공식 Marketplace](https://cyrkl.com/en/marketplace)

별도 Copilot 소개에는 수거·경로 최적화, 계량표 처리, 개별 수거의 비용·수입과 문서 내보내기를 한 업무 흐름에서 관리한다고 설명한다. 이는 공개 제품 설명이며 실제 최적화 성능이나 효과를 재검증하지 않았다. [공식 Copilot 소개](https://cyrkl.com/en/copilot)

**우리 해석:** 기사가 먼저 알아야 하는 재료·위치·수량을 정형화하고, 운송 조건 비교와 이력을 연결할 가치가 있다. 장터의 공급/수요 구분 자체를 운송기사의 새 메뉴로 옮길 필요는 없다. 자동 경로 최적화와 계량표 OCR은 이번 구현에 포함하지 않는다.

### 2. Recykal — 인도 B2B 재활용 자원 거래와 운송 역할

**확인한 사실:** 공식 페이지는 재활용 자원의 기업 간 구매·판매와 거래부터 배송까지의 추적, 송장·증명서·보고서 보관을 소개한다. 다른 공식 랜딩에는 대기 명단 신청이 나타나며, `recykal.market`에는 거래 진입이 있다. 모든 소개 기능이 모든 계정에 제공되는지는 확인하지 못했다. [공식 제품 소개](https://www.recykal.com/recykal-market), [공식 Marketplace](https://recykal.market/)

파트너 페이지는 Recykal Express를 자원 거래에서 발생한 운송 수요를 수행하는 물류 파트너 역할로 설명한다. [공식 파트너 소개](https://www.recykal.market/partners/)

**우리 해석:** 물질의 거래와 이동을 한 주문의 맥락으로 보여 주되, 운송기사에게 판매 가격 결정이나 구매자 검사를 대신 맡기지 않는다. 자원 운송 정보·운송 타임라인을 도입하되 GPS 추적, 에스크로, 보험, 실제 결제·문서 검증을 제공한다고 표현하지 않는다.

### 3. Excess Materials Exchange(EME) — 소재 정보와 재고·거래 작업공간

**확인한 사실:** 현재 공식 주소 `excess.company`는 재료의 품질·상태·위치를 파악하고, 소재 포트폴리오·프로젝트와 재고·거래를 작업공간에서 관리하는 기능을 소개한다. 데모 요청 중심 공개 페이지를 확인했으며 로그인된 실제 작업공간은 검증하지 않았다. [공식 EME 소개](https://www.excess.company/)

**우리 해석:** 소재 이름만 보여 주는 것보다 상태와 출처의 가시성이 중요하다. HW 하윤에서는 등록 등급·등록 중량·기사 확인 중량을 구분한다. 원본에 없는 오염도·처리 방식은 **확인 필요/정보 없음**으로 표시한다. 자동 가치 극대화나 자동 환경성 평가를 구현했다고 주장하지 않는다.

### 4. Rheaply — 미국 기업 자산의 재사용·인수인계

**확인한 사실:** 공식 소개는 기업의 자산 관리와 재사용을 다룬다. 등록 도움말은 상태, 수량, 단위 중량, 위치와 인도 방법을 작성하도록 안내한다. 물류 도움말은 현지 픽업·배송 등의 선택과 메시지를 통한 장소·시간 조율을 설명하며, 현재 전통적인 직접 배송 옵션을 제공하지 않는다고 명시한다. [공식 소개](https://rheaply.com/), [등록 도움말](https://support.rheaply.com/en/articles/6311603-create-a-listing), [물류 도움말](https://support.rheaply.com/en/articles/6311611-ship-move-and-plan-logistics-for-your-listings)

**우리 해석:** 재료 자체의 정보와 옮기는 방법을 함께 노출해야 수락 뒤의 현장 차이를 줄일 수 있다. 따라서 지게차 유무와 수작업 상차 조건을 수락 전에 표시한다. Rheaply를 폐기물 운반 배차 플랫폼이나 직접 운송 서비스로 분류하지 않는다.

### 5. Madaster — 네덜란드·유럽 건축 자재 여권

**확인한 사실:** 공식 소개는 건물에 들어간 자재의 품질·출처·해체 가능성을 기록한다고 설명한다. 도움말은 포함할 정보를 선택하는 PDF 여권, 권한 있는 계정의 객체로 연결하는 QR, 웹 기반 요약 형식을 설명한다. [공식 자재 여권 소개](https://madaster.com/material-passport/), [공식 여권 문서](https://docs.madaster.com/nl/en/knowledge-base/material-passports)

**우리 해석:** 참고할 지점은 정보의 출처와 확인 수준을 한데 모으는 구조다. 새 카드 이름은 **자원 운송 정보**로 정한다. 국내 법정 통과증, 성분 보증서, 폐기물 인계서와 같은 효력을 암시하는 ‘인증 여권’은 만들지 않는다. 공인 분석이 없는 등급·오염도는 검증된 품질처럼 표시하지 않는다.

### 6. Uber Freight — 미국 화물기사의 검색·수락·운송 후 기록

**확인한 사실:** 공식 도움말은 위치·차종·상차일 등으로 화물을 찾고 공차거리, 거리당 운임, 가격, 중량으로 정렬하는 절차와 다음 귀로 화물 안내를 설명한다. 운송 후 도움말에는 POD 제출, 누락 문서 알림이 나온다. [검색·수락 도움말](https://help.uber.com/freight/carrier/article/using-the-uber-freight-app-to-search-and-book-loads?nodeId=dfe69814-ea0d-43e8-ad16-f77621cd2e0c), [운송 중·운송 후 도움말](https://help.uber.com/en/freight/carrier/article/using-the-uber-freight-app-during-and-after-delivery?nodeId=37bbed18-dd0a-47aa-86eb-15b5f73bd0b8)

**우리 해석:** 총 운임만으로 콜을 고르지 않도록 공차 포함 거리와 단위거리 운임을 나란히 둔다. 최대 3개 비교와 조절 가능한 km당 주행비 계산은 **우리의 응용 설계**다. Uber Freight가 이 앱과 같은 비교표·계산식을 제공한다는 근거는 아니다. POD 업로드나 GPS를 흉내 내는 화면은 추가하지 않고 실제 조작 시각 기록부터 구현한다.

### 7. 커버링 — 국내 수거 신청의 정보 공개와 짧은 진입

**확인한 사실:** 방문수거 페이지는 대형 폐기물 품목·수량, 견적 조건, 신청·결제·예약·수거 절차, 가능 지역과 주요 CTA를 안내한다. 커버링에는 빌딩·오피스 대상 서비스도 있으므로 가정용 서비스만 운영한다고 해석하면 안 된다. [방문수거](https://www.covering.app/spot), [빌딩](https://www.covering.app/building), [오피스](https://www.covering.app/office)

**우리 해석:** 수락 전에 핵심 조건을 보여 주고 한 가지 주행동으로 이어지는 구조를 참고한다. 모든 확인 항목에 체크박스를 추가하면 기사에게 불필요한 마찰이 될 수 있다. 차량·상차·허가 정보를 읽기 쉬운 요약으로 제공하고, 기존 운임 입력·유효성 검증을 유지한다. 실제 서비스의 수거 가격이나 품질을 HW 하윤의 조건으로 복사하지 않는다.

## 반영 우선순위

### P0 — 이번 JavaScript 앱 반영 범위

| 기능 | UX·기능 기준 | 참고와 우리 해석 |
|---|---|---|
| 자원 운송 정보 | 품목, 예시 출처, 등록 등급, 등록/기사 확인 중량, 마대 수, 배출자·구매자를 모아 표시. 오염·처리 정보가 없으면 확인 필요 | EME·Madaster의 정보 구조 + 우리 마대 데이터 |
| 최대 3개 콜 비교 | 선택 추가·제거·초기화, 선택 ID 보존, 공차·적재·합계 거리, km당 운임, 예상 주행비, 주행비 차감 참고액 | Cyrkl의 비교 기준과 Uber Freight의 경제성 지표에서 응용 |
| 수락 전 조건 요약 | 차량 적재량, 수작업/지게차 상차, 허가 정보 표시. 기존 수락 검증 유지. 추가 3개 체크박스 없이 핵심 버튼으로 연결 | Rheaply의 인도 조건 + 커버링의 짧은 진입 |
| 운송 타임라인·JSON | 활성 운송과 최근 이력에서 실제 조작 시각, 단계·무게 기록을 표시하고 JSON 내려받기. 참고 정보임을 명시 | Recykal·Cyrkl의 기록 연속성, Uber Freight의 운송 후 문서 흐름에서 범위 축소 |

P0는 실제 기능과 자동검증으로 확인해야 할 이번 반영 항목이다. 이 조사 문서만으로 완료나 테스트 통과를 증명하지 않는다. 최신 결과는 `npm run check`, `npm run test:browser`와 생성된 [브라우저 검증 결과](BROWSER_TEST_RESULTS.json)를 대조한다.

비교는 별도 여섯 번째 메뉴를 만들지 않고 콜 찾기·저장한 콜에서 이어진다. 수락·마대 확인·도착·검사 대기는 기존의 순서와 권한을 따른다. 기사 도착 기록만으로 구매자 검사나 지급 완료를 생성하지 않는다.

### P1 — 후속 제품 설계·운영 검토 뒤 구현

| 후보 | 선행 조건 | 이번에 미구현인 이유 |
|---|---|---|
| 계량표·수령증/POD 첨부 | 저장소·접근권한·보존기간·삭제·분쟁 처리 기준 | 파일 업로드·문서 진위 검증 범위가 없음 |
| 서버 기반 공동 운송 이력 | 역할별 권한, 실제 주문 ID, 동시 갱신·재배차 계약 | 현재 브라우저 로컬 시연 데이터 |
| 귀로 콜·다음 콜 제안 | 시간창·상하차 대기·잔여 적재량·실제 운행 가능 경로 | 가까운 좌표만으로 연속 배차를 보장할 수 없음 |
| 구조화된 오염도·포장·처리 정보 | 공급자 입력 규격, 근거 문서, 구매자 검수·정정 절차 | 현재 데이터에 없는 사실을 만들지 않음 |
| 완전한 차량 비용 설정 | 기사와 합의한 유류·통행료·정비·감가·보험·노무비 모델 | 현재 단일 km당 주행비는 비교용 가정 |
| 실제 허가 확인 연동 | 확인 주체·자료 출처·갱신 주기·코드 대응 검증 | 예시 허가 정보는 공적 조회 결과가 아님 |

### P2 — 먼저 검증할 가설

- 3개 비교가 실제 기사에게 충분한지, 모바일에서 읽기 부담이 없는지 관찰한다.
- 등록 등급·등록 중량·확인 중량을 함께 표시하면 재확인 연락과 현장 불일치가 줄어드는지 확인한다.
- 단일 km당 주행비 설정이 유용한지, 기사가 어떤 비용을 포함했다고 오해하는지 인터뷰한다. 450원/km를 업계 표준으로 가정하지 않는다.
- 수작업 상차 표시와 허가 정보가 수락 전 판단에 필요한지, 자동 검사와 사람 확인을 어디서 나눌지 검증한다.
- 소량 묶음의 구매 수요·공급 밀도·운임·거래 성사 가능성을 파일럿으로 검증한다. 추천 후보 계산만으로 사업 성과를 주장하지 않는다.
- 실제 계량·검수·정산 주체와 분쟁 비용을 확인한 뒤 결제·보험·보증·환경성 수치의 범위를 정한다.

## 이번 기능의 계산·표현 계약

비교 화면은 선택한 콜의 **표시 운임**과 **예상 거리**에 대한 시뮬레이션이다. 표시 운임 상한과 수락 뒤 확정 운임을 섞지 않는다.

```text
총 운행거리(km) = 공차거리 + 적재 운송거리
공차 포함 km당 운임(원/km) = 원 단위 반올림(표시 운임 ÷ 총 운행거리)
예상 주행비(원) = 원 단위 반올림(총 운행거리 × 사용자 설정 주행비(원/km))
주행비 차감 참고액(원) = 표시 운임 − 반올림한 예상 주행비
```

주행비 기본값 **450원/km는 시연용 가정**이다. 사용자가 0~10,000원/km 범위의 **정수**로 조절하며 설정을 보존한다. 거리 표시는 소수 첫째 자리까지지만 계산은 원본 거리 정밀도를 사용한다. km당 운임과 예상 주행비를 원 단위로 반올림하고, 반올림한 주행비를 빼서 참고액을 계산한다. 음수·소수 입력·무한대·잘못된 저장값은 유효성 검사로 처리한다. 거리가 0인 경우 나눗셈 지표를 억지 숫자로 표시하지 않는다.

예를 들어 총 거리 100km, 표시 운임 180,000원, 가정 450원/km이면 1,800원/km, 주행비 45,000원, 주행비 차감 참고액 135,000원이다. 이는 산술 예시이며 **순이익·실수령액·추천 운임이 아니다.** 통행료·상하차 대기·노무·보험·정비·세금 등 모든 원가를 산정하지 않는다. 음수 결과도 숨기지 않는다.

자원 운송 정보의 ‘등록 등급’은 출처가 있는 예시 값을 설명한다. 없는 순도·오염도·처리 방식은 추정하여 채우지 않는다. 타임라인의 날짜는 버튼을 누른 시각이며 GPS 기반 도착 증명이나 공인 시간 증명이 아니다. JSON은 브라우저에 저장된 운송 참고 기록이고 법정 인계서·정산서·공인 재료 여권을 대신하지 않는다.
